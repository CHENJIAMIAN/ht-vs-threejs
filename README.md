# HT for Web 与 Three.js 实现细节对比

**中文** | [English](README.en.md)

> 把 HT for Web 的业务可视化框架逐层拆开，和 Three.js 的实现细节放在一起比：哪些是同一个设计、哪些只是长得像、哪些根本不是一个层级的东西。

## 这是什么

一份 16 章的对比分析文档：以 **HT for Web** 的业务演示工程（泵站、储能电站两个 2D + 3D 案例）为 HT 侧基线，以 **Three.js r125** 源码为 Three.js 侧基线，逐功能域对照两边的实现细节。

文档只包含 Markdown 分析文本，不附带任何第三方库的源码或发行包。

## 三句话结论

1. **不是同一层级的产品**：HT 是「数据模型驱动、一份数据同时喂 2D 拓扑与 3D 场景」的业务框架，Three.js 是「可组合渲染对象」的通用 3D 库。`Node` 不能等同于 `Mesh`。
2. **真正的同源交集在 shader 与数学库**：HT 的 PBR / GGX / 多散射 / cubeUV / PMREM / FXAA 与 Three.js 同源，代码指纹落在 **r133～r136**（不是 r125 本身）；数学库大量方法可逐段比对。
3. **控制权归属相反**：Three.js 把「什么时候渲染、什么时候推进动画」交给应用（`renderer.render` / `mixer.update`）；HT 把这件事收进核心——数据失效自动重绘、全局心跳驱动动画。这是两边最大的架构差异。
